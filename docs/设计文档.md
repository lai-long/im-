## 1. 背景与目标

### 1.1 背景

开发阶段需要将业务系统（如 Agent 平台）接入企业微信进行 IM 消息互通，但企业微信的回调机制要求接入方提供一个**公网可达**的回调 URL，本地开发只能依赖内网穿透，搭建与维护成本高、不稳定。

### 1.2 目标

构建一个**本地运行**的 IM 平台，对外提供与企业微信**群机器人（智能机器人）**接入方式完全一致的 API，使任何按企微机器人规范开发的接入方，仅需修改 API 域名（Base URL）即可完成本地联调，无需内网穿透。

协议基线已于 2026-08-28 对照企微官方文档逐字段核对并锁定，见 §7.4。后续实现与验收以该基线为准；基线之外的企微行为以 §1.5 兼容性边界为准。

具体目标（按优先级）：

1. **机器人发送兼容（P0）**：`POST /cgi-bin/webhook/send?key=xxx`，请求体、msgtype、错误码与企微一致。
2. **机器人接收兼容（P0）**：平台把用户在群里的消息（含 @机器人）按智能机器人回调格式推送给接入方——URL 验证（echostr 握手）+ 加密信封（Token + EncodingAESKey + msg_signature，信封体 `{"encrypt": "..."}`），接入方可直接复用企微官方加解密库（WXBizMsgCrypt）。
3. **机器人回复链路兼容（P0）**：被动回复（流式 stream / 模板卡片）+ response_url 主动回复 + webhook/send 无上下文群发，三条路径与企微一致（见 §4.3）。
4. **客户端替身（P0）**：Web 群聊客户端扮演"企业微信 App 端"——用户在网页登录、进群、收发消息、@机器人。
5. **自建应用兼容（P1，后移）**：gettoken + message/send + 加密 XML 回调，供需要应用消息形态的接入方使用。
6. **零依赖部署（P0）**：单二进制 + 本地文件数据库（SQLite），一条命令启动，启动即输出可用的接入信息（开箱即用，见 §4.7）。

### 1.3 为什么本地平台（而非官方长连接）

企微智能机器人已提供**长连接模式**（接入方主动外连 wss，无需公网 IP），官方层面解决了内网穿透问题。但本地平台仍有独立价值：

- 不需要真实企业与管理员审批，**任何开发者/项目即刻可用**；
- 完全离线可用，不依赖企微服务的可用性与配额、频控；
- 消息全量落库可观测，联调排障方便；
- 多接入方各自创建机器人，天然隔离，互不影响。

平台对长连接协议的同形模拟列为 P2（见 §7.3）。

### 1.4 非目标

- 不做真实多租户 SaaS、集群、高可用——单机单实例。
- 不实现企微全部 API（审批、日程、JS-SDK 等不做），只覆盖 IM 接入闭环所需子集。
- 不做端到端加密——加密仅为协议兼容，本地环境不追求真实安全性。
- 不模拟企微的运营性行为（限频、审核等）。具体包括：回复/推送频控（官方 30 条/分钟、1000 条/小时）、"同一用户与机器人最多 3 条并发交互中"限制、敏感词审核。

### 1.5 兼容性边界（与企微的已知差异）

以下差异是平台定位决定的**有意为之**或**无法消除**的环境差异，接入方迁移时需知晓。除此表之外的行为，均以"与企微一致"为验收标准。

| 差异点 | 企微行为 | 平台行为 | 对接入方的影响 |
|---|---|---|---|
| 传输协议 | 全链路 HTTPS | 默认 HTTP；TLS（自签证书）可一键开启 | 强制 https 的 SDK 需开启平台 TLS 并信任自签 CA |
| Base URL 硬编码 | `qyapi.weixin.qq.com` | 任意地址 | 支持自定义 Base URL 的 SDK/裸 HTTP 客户端无影响；硬编码域名的 SDK 需 hosts 劫持兜底（M3 脚本） |
| 鉴权数据来源 | 企微管理后台分配 | 平台控制台生成 | 配置来源不同，格式一致 |
| `from.userid` | 超管创建的机器人为明文 userid，否则为加密 userid | 恒为明文 userid（对齐"超管创建"场景） | 接入方若实现了加密 userid 转换逻辑，本地联调时该分支不触发 |
| msgid 格式 | base64 串（如 `CAIQ16HMjQYY...`） | 全局递增 id 的同形 base64 编码 | 仅保证唯一性与排重语义，不要解析其内容 |
| 频控与并发限制 | 30 条/分钟、1000 条/小时；同用户最多 3 条交互中 | 不模拟 | 本地联调不会触发限频分支，相关容错逻辑需上线前在真机验证 |
| 图片/文件回调的下载 URL | 加密 COS 文件，5 分钟有效 | 平台本地 URL 同形模拟，文件按相同 AES 方案加密（P1） | 接入方解密代码路径一致 |
| 回调源 IP | 企微服务器 IP 段（getcallbackip） | 本机/局域网 IP | 接入方若做 IP 白名单需放开 |
| response_url 可达地址 | 企微公网域名 | 启动配置 `-public-url` 生成的平台对外地址（缺省用监听地址） | 接入方与平台不同机时需配置局域网地址 |
| 流式刷新轮询节奏 | 官方未公开 | 固定 1s（可配置） | 接入方应以 `finish` 标志驱动状态机，不应依赖轮询节奏 |

## 2. 术语

| 术语 | 说明 |
|---|---|
| 平台 | 本项目，本地 IM 平台，运行在开发者本机 |
| 接入方 | 需要接入 IM 的业务系统（如 Agent 平台），即"使用企微机器人 API 的那个服务" |
| 机器人（bot） | 对齐企微"智能机器人"：拥有 webhook key（群发）+ 回调配置（接收）+ aibotid。**平台的核心实体** |
| 群（chat） | 对齐企微群聊 `chatid`，机器人所在群 |
| 客户端 | 平台自带的 Web IM 界面，模拟企业微信 App |
| 用户（userid） | 群成员，在客户端上使用 |
| 应用（agent） | 对齐企微"自建应用"，P1 阶段的扩展实体 |
| response_url | 回调中携带的一次性主动回复地址，对齐企微 `/cgi-bin/aibot/response?response_code=xxx` |

平台扮演两个角色：

- **企微"云端"替身**：API 兼容层（webhook/send、aibot/response）+ 回调分发器（智能机器人回调）。接入方像调用 `qyapi.weixin.qq.com` 一样调用它。

## 4. 核心设计决策

### 4.1 API 路径与结构完全对齐企微

- 路径保持 `/cgi-bin/webhook/send`、`/cgi-bin/aibot/response` 等原样，不做任何"本地化改名"。
- 请求体 JSON 字段、`errcode`/`errmsg` 错误结构、错误码数值与企微一致。错误码不做"按需对齐"的模糊承诺——P0 交付一份**错误码对照表**（平台已实现的每个错误码逐条标注官方出处与触发条件），随版本维护，落盘 `docs/错误码对照表.md` 并同步机器可读 `docs/errorcodes.json`（接入方测试可直接导入）。
- 接入方唯一需要改的是 Base URL：`https://qyapi.weixin.qq.com` → `http://127.0.0.1:7788`（或局域网 IP）。
- **SDK 兼容性**：机器人 URL 回调模式下，主流接入方式是"裸 HTTP 服务 + 官方 WXBizMsgCrypt 加解密库"，加解密库不依赖任何域名，天然兼容；webhook/send 与 aibot/response 均为普通 HTTP 调用。对少数把 `qyapi.weixin.qq.com` 硬编码进代码的 SDK，提供 hosts 劫持 + 自签证书兜底（M3 脚本）。P0 验收须产出**已验证接入方式清单**（至少覆盖 curl 与一种官方加解密库语言版本）。
- **传输协议**：企微全链路 HTTPS，平台默认 HTTP。为兼容强制 https 的接入方，TLS（自签证书）一键开启能力提前至 P0。

### 4.2 机器人回调双轨制：加密模式与明文模式

每个机器人可独立选择回调模式：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| **加密模式（默认）** | URL 验证（echostr 解密应答）+ 消息以企微智能机器人格式经 AES 加密信封推送（POST body 为 `{"encrypt": "..."}`，URL 带 `msg_signature`/`timestamp`/`nonce`） | 接入方复用企微 SDK/加解密代码，验证完整链路 |
| **明文模式** | URL 验证直接回显 echostr；消息以未加密 JSON 推送；被动回复的应答 body 亦为未加密 JSON（不加密、不做 msg_signature 校验） | 本地快速联调、抓包排查 |

设计理由：加密信封（Token + EncodingAESKey + SHA1 签名 + AES-CBC）与企微各回调场景同源，一套实现同时服务 P0 机器人回调与 P1 自建应用回调；明文模式降低调试成本。两种模式的推送与重试行为完全一致。

加密关键差异点（已核对，见 §7.4）：智能机器人场景中 WXBizMsgCrypt 的 `receiveid` 参数为**空字符串**（自建应用场景为 corpid）；加解密库其余部分完全复用。

回调明文载体为**智能机器人 JSON 格式**，字段名以官方为准：`msgid`、`aibotid`、`chatid`、`chattype`、`from.userid`、`response_url`、`msgtype` 等（完整基线见 §7.4）。

### 4.3 回复链路：三条路径，与企微一一对应

企微智能机器人 URL 回调模式下，接入方回复消息有三条路径，平台全部模拟：

1. **被动回复**：接入方在回调的 HTTP 应答中直接返回加密的回复包体（`{"encrypt": "..."}`），平台解密后落群。**类型限制与企微一致**：回复用户消息时仅支持流式消息（`stream`，含 `finish` 标记与全量刷新语义）与模板卡片（`template_card` / `stream_with_template_card`）；`text` 仅"进入会话欢迎语"场景支持。接入方应答空串或 `success` 表示不回复。
2. **response_url 主动回复**：每条消息回调携带 `response_url`（形如 `{BaseURL}/cgi-bin/aibot/response?response_code=xxx`），接入方可异步 POST 回复（markdown / template_card）。与企微一致：**每个 response_url 仅可调用一次，有效期 1 小时**；群聊中主动回复的消息自动引用触发它的用户消息。
3. **webhook/send 群发**：机器人随时向所在群推送消息，无上下文、无引用。这是经典群机器人唯一的发送方式，也适用于告警类无上下文通知。

> 注：v0.2 曾把"webhook/send 回复"当作主用路径——经核对官方文档，智能机器人场景下"回复用户消息"的正主路径是被动回复与 response_url，webhook/send 是无上下文群发。三者语义不同，平台均需支持。

流式回复（URL 模式）机制与企微一致：接入方首次被动回复 `finish=false` 的 stream 消息后，平台向回调 URL 轮询推送"流式消息刷新"回调（`msgtype=stream`，带 `stream.id`），接入方在每次应答中返回全量新内容，直至 `finish=true`；自用户消息起最长 6 分钟。该能力为 URL 回调模式的**主路径**，列入 P0。轮询节奏官方未公开，平台取固定 1 秒（可配置）；接入方应以 `finish` 标志驱动状态机，不应依赖节奏（见 §1.5）。

### 4.4 身份模型：预置企业 + 机器人

- 初始化时自动创建默认企业（`corpid` 形如 `ww_local_xxxxx`）与一个默认群。
- 接入方在管理控制台创建机器人，平台生成：
  - `aibotid`（形如企微智能机器人 id 格式）
  - 回调配置：`URL`、`Token`（不超过 32 位）、`EncodingAESKey`（43 位，可由平台生成或接入方填写）
- 控制台把机器人"拉进"群时，为该 **(bot, chat) 关系**生成独立的 `webhook_key`（形如企微 UUID 格式）——对齐企微语义：同一机器人加入多个群，每个群的 webhook key 不同；`/cgi-bin/webhook/send?key=xxx` 由此唯一定位目标群。
- 用户 @机器人 消息路由到该机器人的回调（回调配置为 bot 级，全群共用）。

### 4.5 群聊会话模型

- 用户 ↔ 群：普通群聊成员关系，客户端内实时收发（WS）。
- 机器人 → 群：webhook/send / 被动回复 / response_url 主动回复的消息均以机器人身份落入目标群。
- 用户 → 机器人：用户在群里发送含 @机器人 的消息（对齐企微真实行为：只有 @机器人 或机器人单聊才触发回调），生成回调任务。
- 机器人单聊（`chattype=single`，用户与机器人的私聊会话触发回调）列为 P1。

### 4.6 数据全部本地持久化

SQLite 单文件 + 素材文件目录。重启不丢数据（与现有 demo 的内存态不同），便于长期联调与回归。

### 4.7 开箱即用

- 初始化除默认企业/群/用户外，**预置一个示例机器人**（已在默认群内，webhook key 固定或可预测，回调三元组已生成待填 URL）。
- 启动日志直接打印接入信息：webhook/send 完整 URL（基于 `-public-url` 生成，缺省用监听地址）、回调三元组、控制台与客户端地址。
- README 提供 5 分钟冒烟流程（见 §8.4 迁移清单的 curl 用例）。

## 5. 模块设计

### 5.1 API 兼容层（`/cgi-bin/*`）

职责：按企微规范完成鉴权、参数校验、错误码返回，转发给消息核心。

- **P0 — 机器人**：
  - `POST /cgi-bin/webhook/send`：校验 `key`；msgtype：`text`、`markdown`（P0），`markdown_v2`/`image`/`news`/`file`/`voice`/`template_card`（P1）；`mentioned_list`/`mentioned_mobile_list` @ 语法；text/markdown 支持 `<@userid>` 扩展语法。
  - 长度限制与企微一致：text content ≤ 2048 字节，markdown ≤ 4096 字节；image 为 base64+md5（base64 前 ≤ 2M，JPG/PNG）。
  - `POST /cgi-bin/aibot/response?response_code=xxx`：response_url 主动回复（一次性、1 小时有效）。
  - 错误码子集：0（ok）、93000（无效 webhook key / 机器人被移出群）等，全部收录于随版本维护的错误码对照表（见 §4.1）。
- **P1 — 自建应用**：`gettoken`（corpid+corpsecret → access_token，7200s）、`message/send`（touser 多用户、invaliduser 返回）、token 失效 40014/42001 驱动 SDK 刷新。
- **P1 — 机器人素材**：`POST /cgi-bin/webhook/upload_media?key=xxx&type=file|voice`，供 file/voice 消息获取 media_id（企微群机器人专用素材接口，与自建应用 media/upload 不同）。

### 5.2 管理控制台（`/admin` + Web UI）

- 机器人管理：创建、查看/重置 webhook key 与回调三元组、配置回调（URL/Token/AESKey/模式）、在线验证回调连通性（模拟企微"保存回调配置"时的 echostr 握手）。
- 群管理：建群、成员管理、把机器人拉入/移出群。
- 用户管理：创建用户、查看在线状态。
- 消息观测：按群/机器人维度查看消息流水与回调投递状态（联调时最重要的排障入口）；死信查看与手动重推，并支持**任意历史消息手动重推（回调重放）**——联调接入方处理逻辑时无需重新发消息。
- 控制台仅本机/局域网访问，默认免鉴权，可配置口令。

### 5.3 消息核心

- 群会话管理：群、成员、机器人关联。
- 消息生命周期：`created → routed → delivered(客户端) → callback_pushed`。
- msgid：全局递增（对齐企微 msgid 的唯一性与排重语义），接入方幂等去重依据。
- **@ 解析**：客户端发送时解析 `@机器人名`/@ userid 与 `mentioned_list`，命中群内机器人即生成回调任务。
- 消息类型：主动发送——text、markdown（P0），image、news、file、voice、markdown_v2、template_card（P1）；回复路径（被动回复 / response_url）——stream、template_card（P0）。入库存 JSON 原文，投递时按目标渲染。

### 5.4 回调分发器

职责：把"用户发给机器人"的消息按智能机器人格式推给接入方。

- 队列：每机器人一个内存队列 + SQLite 持久化（pending 状态），崩溃恢复后继续推送。
- 重试：非 2xx 或超时（5s，对齐企微"5 秒收不到响应即重试"）即重试，最多 3 次；仍失败记死信，控制台可见并支持重推。
- 应答判定（加密模式）：HTTP 200 且 body 为空串 / `success`（无回复），或 body 为合法 JSON `{"encrypt": "..."}` 且解密验签成功（有被动回复，解密后落群）视为成功；解密失败或格式非法按失败重试。
- 顺序：单机器人串行推送保证消息顺序；跨机器人并行互不影响。
- 流式轮询：被动回复为 `finish=false` 的 stream 消息时，按 §4.3 机制继续向回调 URL 推送流式刷新回调（同样走加密信封与重试），直至 `finish=true` 或到达 6 分钟窗口。

### 5.5 WS 网关（客户端通道）

- 客户端登录后建立 WebSocket，接收实时消息、在线状态、群变更。
- 多端登录允许多连接并存（多开浏览器标签模拟多用户）。

### 5.6 存储

- SQLite：企业、机器人、群、用户、消息、回调投递记录、素材映射；（P1）应用、access_token。建库与升级走内嵌迁移脚本（`schema_version` 表记录版本），字段演进不手工改库。
- 素材：`media_id` → 本地文件映射表 + 文件目录；客户端经平台内部接口拉取渲染。

**回调明文 JSON（文本消息，群聊场景）：**

```json
{
  "msgid": "CAIQ16HMjQYY/NGagIOAgAMgq4KM0AI=",
  "aibotid": "AIBOTID",
  "chatid": "CHATID",
  "chattype": "group",
  "from": { "userid": "USERID" },
  "response_url": "https://qyapi.weixin.qq.com/cgi-bin/aibot/response?response_code=RESPONSE_CODE",
  "msgtype": "text",
  "text": { "content": "@RobotA hello robot" },
  "quote": { "msgtype": "text", "text": { "content": "被引用的消息" } }
}
```

- `chatid` 仅群聊返回；单聊 `chattype=single` 无 `chatid`。
- `quote` 仅在用户引用消息时携带（P1）。
- 平台生成 `response_url` 时使用平台自身 Base URL，其余格式不变。

**流式消息刷新回调（平台轮询接入方）：**

```json
{
  "msgid": "...",
  "aibotid": "AIBOTID",
  "chatid": "CHATID",
  "chattype": "group",
  "from": { "userid": "USERID" },
  "msgtype": "stream",
  "stream": { "id": "STREAMID" }
}
```

**被动回复包体（应答回调的 HTTP body，加密模式为 `{"encrypt": ...}`，明文如下）：**

```json
{
  "msgtype": "stream",
  "stream": {
    "id": "STREAMID",
    "finish": true,
    "content": "**广州**今日天气：29度，大部分多云"
  }
}
```

- `stream.id` 首次回复必填，后续刷新回调用同一 id 获取更新；`content` 为**全量**内容（非增量），≤ 20480 字节，支持 markdown 与 `<think>` 标签。
- `finish=true` 表示流式结束；一次性回复直接 `finish=true`。

## 8. 关键流程时序

### 8.1 接入方发消息到群

```
接入方                         平台API            消息核心        客户端(群成员)
  │ POST /cgi-bin/webhook/send    │                 │                │
  │   ?key=xxx {"msgtype":"text"} │                 │                │
  │──────────────────────────────►│ 校验key/落库     │                │
  │◄─ {"errcode":0,"errmsg":"ok"}─│                 │                │
  │                               │ ── WS 推送 ─────────────────────►│ 群内出现机器人消息
```

### 8.2 用户 @机器人 → 回调接入方 → 回复

```
客户端(用户)      平台WS网关       消息核心       回调分发器        接入方
  │ "@bot 今天天气如何"  │             │              │               │
  │─────────────────────►│ 落库+解析@   │              │               │
  │                      │────────────►│ 生成回调任务   │               │
  │                      │             │─────────────►│ 加密信封       │
  │                      │             │              │ POST {"encrypt"│
  │                      │             │              │  :...} ───────►│ 官方加解密库验签解密
  │                      │             │              │ (5s超时,重试3次)│
  │                      │             │              │◄─{"encrypt":..}│ 加密被动回复(stream)
  │                      │             │              │ 或 200 success │
  │  机器人回复落群        │             │              │               │
  │◄─(被动回复或WS推送)────│◄────────────│◄─────────────│               │
  │                      │  接入方也可异步用回调中的 response_url 主动回复（一次性、1h 有效）
  │                      │  或用 POST /cgi-bin/webhook/send 无上下文群发（同一 Base URL）
```

流式分支：被动回复 `finish=false` → 回调分发器继续向接入方推送流式刷新回调（`msgtype=stream` + `stream.id`）→ 接入方每次应答全量新内容 → 直至 `finish=true` 或 6 分钟窗口结束。

### 8.3 回调配置验证（控制台"保存回调"）

```
控制台              回调分发器         接入方
  │ 保存URL/Token/AESKey │               │
  │──────────────────────►│ GET url?msg_signature&timestamp&nonce&echostr
  │                       │──────────────►│
  │                       │◄─ 解密后明文echostr（加密模式）───│
  │                       │ 校验通过 → callback_verified=1
  │◄─ 验证结果 ────────────│
```

对齐企微要求：接入方须在 1 秒内应答，响应为解密后的明文 echostr（无引号、无 BOM、无换行）。

### 8.4 接入方迁移清单（5 分钟冒烟）

从真实企微接入迁移到本平台，接入方需要做的全部改动：

1. **改 Base URL**：`https://qyapi.weixin.qq.com` → 平台地址（启动日志可见）。
2. **换 webhook key**：从平台控制台（或启动日志）获取示例机器人在默认群的 key（key 按群分配）。
3. **换回调三元组**：接入方回调服务的 Token/EncodingAESKey 改为平台控制台所示值；WXBizMsgCrypt 的 `receiveid` 参数置空字符串；回调 URL 填接入方本机地址（平台接受内网 URL）。
4. **验证握手**：控制台保存回调配置，观察验证通过。
5. **冒烟**：
   - `curl -X POST '{平台}/cgi-bin/webhook/send?key=xxx' -d '{"msgtype":"text","text":{"content":"hello"}}'` → 客户端群内可见。
   - 客户端 @机器人 发消息 → 接入方收到加密回调并能解密；被动回复 `{"msgtype":"stream","stream":{"id":"s1","finish":true,"content":"pong"}}` → 群内出现回复。

已知不能直接迁移的情形：SDK 硬编码企微域名（需 hosts + 自签证书兜底）；依赖真实企微用户体系/加密 userid 的逻辑（见 §1.5）。

## 9. 可靠性设计

- **幂等**：接入方按 `msgid` 去重（企微同款约定）；平台按 `callback_task` 单任务至少一次推送。
- **重试**：见 5.4，对齐企微 5 秒超时、最多重推 3 次。
- **顺序**：单机器人回调队列串行，保证消息顺序。
- **崩溃恢复**：pending/重试中的回调任务持久化在 SQLite，进程重启后继续。
- **流式状态**：`stream_id` / `stream_finished` 持久化，重启后未完成的流式会话按超时结束处理（企微 6 分钟窗口语义）。

## 10. 安全设计

本地开发工具定位，安全目标为"协议正确"而非"防攻击"：

- 通信：默认 HTTP 明文（本地/局域网可接受）；提供 TLS 开关（自签证书）以兼容强制 HTTPS 的接入方。
- 鉴权：webhook key / response_code 校验走完整流程以验证接入方逻辑；控制台默认免鉴权，可设口令。
- 加密回调的 AES/signature 实现严格对齐 WXBizMsgCrypt 规范（AES-256-CBC、PKCS7、SHA1 签名，机器人场景 receiveid 为空字符串），其价值在于**兼容性验证**而非保密性。

## 11. 约束与权衡

| 权衡点 | 决策 | 理由 |
|---|---|---|
| 机器人 vs 自建应用优先 | 机器人先行（P0），自建应用 P1 | 用户主用 webhook 双向；机器人协议轻、闭环小 |
| 回调载体 JSON vs XML | 机器人用 JSON（智能机器人格式）；自建应用 P1 用 XML | 各自对齐对应企微场景的原生格式 |
| 回复路径 | 被动回复 + response_url + webhook/send 三条全模拟 | 三者语义不同，企微均有真实用途（§4.3） |
| 流式回复 | URL 模式流式提前至 P0 | 它是智能机器人 URL 回调模式回复用户消息的主路径，缺失则多数 Agent 接入方无法联调 |
| SQLite vs 内存 | SQLite 持久化 | 长期联调、消息流水排障 |
| 单进程 vs 微服务 | 单进程 | 本地工具，部署简单优先 |
| 长连接协议模拟 | P2 可选 | 价值高但工作量大，回调 URL 模式已满足"接入方式相同" |
