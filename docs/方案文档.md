## 1. 概述

本方案说明如何落地设计文档所述的"企业微信兼容本地 IM 平台"：技术选型、项目结构、分期计划、关键实现细节、部署方式与验收标准。核心兼容目标为**群机器人（智能机器人）双向模式**——webhook 发送 + 加密回调接收 + 流式/主动回复。

现状：仓库内 `testweb/` 是一个验证思路的简易 demo（Go + React、内存态、群聊 + 自有 webhook 协议）。新平台**独立重建**，不复用 demo 代码结构；但 demo 的"群聊客户端 + webhook"形态恰好是智能机器人的最小写照，架构经验直接延续。

### 1.1 企业微信接入方式概览

企业微信对外的 IM 接入主要有五种方式，能力与接入复杂度差异很大：

**方式一：群机器人 / 智能机器人 —— 本平台的核心兼容目标**

- 面向**群聊**，在企微客户端群设置中添加机器人（经典群机器人），或在管理后台以"API 模式"创建智能机器人
- **发送**：`POST /cgi-bin/webhook/send?key=xxx`，请求体即 JSON：
  `{"msgtype":"text","text":{"content":"...","mentioned_list":["userid","@all"]}}`
  支持 text / markdown / markdown_v2 / image（base64+md5）/ news / file / voice / 模板卡片；无需 access_token，webhook key 即鉴权；file/voice 需先经 `webhook/upload_media` 获取 media_id
- **接收（智能机器人）**：配置回调 URL + Token + EncodingAESKey；企微先做 URL 验证（echostr 解密回显握手），之后把用户 @机器人 或机器人单聊的消息经**加密信封**（AES + msg_signature，信封体 `{"encrypt": "..."}`，与自建应用同源加解密，但 receiveid 为空字符串）推送给接入方，载体为 JSON（`msgid`、`aibotid`、`chatid`、`chattype`、`from.userid`、`response_url`、`msgtype`、`text.content` 等）
- **回复**：三条路径——①被动回复（回调应答中返回加密回复，回复用户消息仅支持 stream / template_card，text 仅欢迎语场景）；②response_url 主动回复（回调中携带的一次性地址，`POST /cgi-bin/aibot/response?response_code=xxx`，1 小时有效，支持 markdown/template_card）；③webhook/send 无上下文群发。流式消息为 URL 模式主路径：`finish=false` 后企微轮询推送"流式消息刷新"回调，接入方每次应答全量新内容，最长 6 分钟
- **长连接模式**：智能机器人可不用回调 URL，改为接入方主动外连 `wss://openws.work.weixin.qq.com`，以 `aibot_subscribe`（bot_id + secret）鉴权后接收 `aibot_msg_callback` / `aibot_event_callback` 帧——官方层面**免公网 IP**；官方 Node SDK：`@wecom/aibot-node-sdk`
- 经典群机器人（仅群内添加、只拿 webhook）**只能发不能收**；双向必须走智能机器人回调/长连接
- 适合：Agent、告警、群内问答机器人——**接入成本最低的双向方式**

**方式二：自建应用（应用消息）—— 平台 M2 兼容目标**

- 面向企业内部，管理后台创建自建应用，获得 `corpid` + `corpsecret` + `agentid`
- 鉴权：`GET /cgi-bin/gettoken` 换 `access_token`（7200s）
- 主动发消息：`POST /cgi-bin/message/send`（touser/toparty/totag 定向，`|` 多用户、`@all`）
- 接收消息：配置"接收消息服务器"（URL + Token + EncodingAESKey），URL 验证同机器人；消息以 **AES 加密 XML** 回调推送（与机器人回调同一套加解密，receiveid 为 corpid，载体为 XML）
- 可选：OAuth2 网页授权
- 适合：内部系统、审批通知等点到点（应用↔用户）双向场景

**方式三：微信客服**

- 面向企业**外部**微信用户，创建客服账号（kf_account），客服 secret 换 token
- 客户消息 → 加密回调推给接入方（事件+消息混合）→ 接入方调 `POST /cgi-bin/kf/send_msg` 回复；会话 48 小时内有效，另有 5 分钟被动回复窗口
- 适合：对外客服、售前咨询（testweb demo 当初对标的就是 企微/微信客服）

**方式四：客户联系（外部联系人）**

- 企业成员添加客户微信后，系统以**成员身份**（客户联系 secret）读取外部联系人、发消息、管理客户群；消息经成员账号触达客户，受成员授权与合规约束
- 适合：SCRM、销售跟进

**方式五：第三方应用 / 代开发应用（服务商）**

- 服务商在企微开放平台上架应用被多企业安装；鉴权多一层套件体系（`suite_ticket` → `suite_access_token` → 企业授权码换 token）；回调加密同源自带多租户维度
- 适合：ToB 服务商；单企业内部接入用不到

**对比与本平台取舍：**

| 方式 | 方向 | 鉴权 | 回调载体 | 接入复杂度 | 本平台策略 |
|---|---|---|---|---|---|
| 群/智能机器人 | 双向（群） | webhook key | 加密信封 + JSON | **低** | **M1 核心目标** |
| 自建应用 | 双向（应用↔用户） | corpid+secret+agentid | 加密信封 + XML | 中 | M2 完整兼容 |
| 微信客服 | 双向（外部用户） | 客服 secret | 加密信封 | 高 | 远期可选 |
| 客户联系 | 双向（经成员账号） | 客户联系 secret | 加密信封 | 高 | 不做 |
| 第三方/代开发 | 双向（多租户） | suite 套件体系 | 加密信封 | 高 | 不做 |

取舍理由：

1. 用户**主要使用 webhook**：机器人是接入成本最低的双向方式（无需 token 流程），M1 全力做好它的收发闭环。
2. 机器人与自建应用的回调加解密**同一套**（WXBizMsgCrypt，仅 receiveid 取值不同），M1 建好的加密基建在 M2 直接复用，后移成本低。
3. 微信客服与机器人/自建应用协议同源，列为远期方向。
4. 客户联系 / 第三方应用与"本地开发联调"诉求无关，明确不做。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Go | demo 已验证；单二进制分发；标准库 HTTP/WS 足够 |
| 存储 | SQLite（`modernc.org/sqlite`，纯 Go 免 CGO） | 零外部依赖；单文件备份 |
| 前端 | React + TypeScript + Vite | 延续 demo 技术栈；`go:embed` 打进单二进制 |
| WebSocket | `nhooyr.io/websocket` 或 `gorilla/websocket` | 成熟稳定（客户端网关；M3 长连接同形端点复用） |
| 加解密 | Go 标准库 `crypto/aes` + `crypto/sha1` | WXBizMsgCrypt 自实现，规范公开 |
| HTTP 路由 | `net/http` + `http.ServeMux`（Go 1.22+ 支持方法与路径参数） | 避免引入框架 |

产出物：**一个二进制** `im-server` + 一个数据目录（`im.db` + `media/`）。

## 4. 分期实施

### M1a —— 机器人双向闭环（一次性回复，先行）

目标：接入方改一个 Base URL，跑通"webhook 发消息到群 + 群里 @机器人收到加密回调 + 一次性被动回复 / response_url 回复落群"。接入方联调在 M1a 即可开始。

- **开箱即用**：初始化默认企业、默认群、2 个示例用户、**1 个已入群的示例机器人**（默认群的 webhook key 固定可预测、回调三元组已生成待填 URL）；启动日志直接打印接入信息（webhook/send 完整 URL 基于 `-public-url` 生成、回调三元组、控制台与客户端地址）
- `POST /cgi-bin/webhook/send`：key 鉴权（key 按群分配）、`text`/`markdown`、`mentioned_list`/`mentioned_mobile_list`、`<@userid>` 语法、长度限制与错误码对齐
- 机器人回调：控制台配置 URL/Token/AESKey + 在线验证握手；**加密模式**推送 `{"encrypt":...}` 信封 + JSON 载体（完整 WXBizMsgCrypt，receiveid 为空字符串）；5s 超时、重试 3 次；死信落库
- **被动回复（一次性）**：接入方在回调应答中返回加密的 `finish=true` stream 回复，平台解密落群；类型限制对齐官方（text 被动回复按官方语义拒绝并记日志，欢迎语场景 M2）
- **response_url 主动回复**：`POST /cgi-bin/aibot/response?response_code=xxx`，一次性、1 小时有效，支持 markdown
- Web 客户端：登录二选一（选择预置用户 / 输入昵称自动注册 userid，免密）、群聊界面、收发文本/markdown、@机器人自动补全
- 控制台：机器人/群管理、消息流水与回调投递状态查看
- **交付物**：`docs/错误码对照表.md` + `docs/errorcodes.json`（机器可读）；`examples/pingbot-go`、`examples/pingbot-python`（官方 WXBizMsgCrypt 库）；`make selftest`（回环自测，见 §5.7）
- **协议基线已锁定**（2026-08-28，见设计文档 §7.4）：实现期逐字段对照官方文档，发现与基线偏差即停线修正并回写文档

### M1b —— 流式回复、模板卡片与 TLS

- **流式回复（URL 模式）**：`finish=false` 后按固定节奏（默认 1s，可配置）轮询推送流式刷新回调（`msgtype=stream` + `stream.id`），全量刷新语义，6 分钟窗口；`finish=true` 结束；客户端流式消息分段渲染
- **template_card**：被动回复与 response_url 支持
- **TLS**：自签证书一键开启（兼容强制 https 的接入方）
- **selftest 扩展**：覆盖流式、template_card、TLS 全链路
- 错误码对照表补全

### M2 —— 自建应用兼容 + 机器人增强

- 自建应用：`gettoken`（多 token 共存与过期）、`message/send`（touser 多用户、invaliduser）、加密 XML 回调（receiveid=corpid）——复用 M1 加密基建
- `webhook/send` 扩展：markdown_v2、image、news、file、voice、template_card
- `webhook/upload_media`（机器人素材）与 `media/upload` / `media/get`（自建应用素材），客户端渲染图片
- 明文回调模式（调试开关，机器人与应用共用）
- 机器人单聊（`chattype=single`）、图文混排 mixed、引用 quote
- 进入会话事件与欢迎语被动回复
- 通讯录只读：`user/get`、`user/simplelist`；错误码补全
- 死信管理：控制台查看/重推；任意历史消息手动重推（回调重放）

### M3 —— 完整体验

- 智能机器人**长连接模式**同形模拟：本地 wss 端点，`aibot_subscribe` / `aibot_msg_callback` / `aibot_event_callback` / `aibot_respond_msg`（对照官方文档 101463/101836 与 `@wecom/aibot-node-sdk`）
- 模板卡片交互事件（按钮/选择器回调、`update_template_card`）
- OAuth2 网页授权闭环、应用群聊（`appchat/send`）
- hosts 劫持适配脚本（针对硬编码企微域名的 SDK）
- 消息导出、会话级消息回放

## 5. 关键实现点

### 5.1 WXBizMsgCrypt（`internal/callback/crypt.go`）

规范（企微官方公开文档，机器人回调与自建应用回调共用）：

- `AESKey = Base64Decode(EncodingAESKey + "=")`，32 字节，AES-256-CBC，IV 取 key 前 16 字节
- 明文结构：`random(16B) + msg_len(4B, 网络字节序) + msg(UTF-8) + receiveid`
- **receiveid 取值（已核对）**：智能机器人回调为**空字符串**；自建应用回调为 corpid
- 填充：PKCS7(32)
- 签名：`SHA1(sort(token, timestamp, nonce, 密文))` → `msg_signature`
- 密文输出：Base64；机器人场景的信封为 JSON `{"encrypt": "..."}`，自建应用场景为 XML `<Encrypt>`

实现 4 个函数：`Encrypt(plain, aesKey, receiveid)`、`Decrypt(encrypted)`、`Signature(token, ts, nonce, encrypted)`、`VerifyURL(...)`。用官方测试向量写单元测试保证字节级正确；M1 验收要求接入方用官方加解密库实测互通。

### 5.2 webhook/send 请求与响应

请求（对齐企微）：

```json
POST /cgi-bin/webhook/send?key=xxxx-xxxx-xxxx
{"msgtype":"text","text":{"content":"通知内容","mentioned_list":["u1","@all"]}}
```

- 响应：`{"errcode":0,"errmsg":"ok"}`；key 无效返回 93000 等，逐条对齐并收录于错误码对照表。
- `mentioned_list` 命中平台用户 → 群内产生 @ 提醒（客户端渲染）；text/markdown 支持 `<@userid>` 扩展语法。
- 长度限制对齐：text content ≤ 2048 字节，markdown ≤ 4096 字节。

### 5.3 机器人回调推送（明文载体，加密前）

按智能机器人官方 JSON 格式推送（2026-08-28 已核对，见设计文档 §7.4）：

```json
{
  "msgid": "CAIQ16HMjQYY/NGagIOAgAMgq4KM0AI=",
  "aibotid": "AIBOTID",
  "chatid": "CHATID",
  "chattype": "group",
  "from": { "userid": "USERID" },
  "response_url": "http://127.0.0.1:7788/cgi-bin/aibot/response?response_code=XXX",
  "msgtype": "text",
  "text": { "content": "@bot 今天天气如何" }
}
```

明文模式直接 POST 此 JSON；加密模式包进 `{"encrypt": ...}` + `msg_signature` 后推送。`response_url` 使用平台自身 Base URL 生成，`response_code` 一次性、1 小时有效。

### 5.4 回调分发器

- 每机器人一个 goroutine 消费持久化队列（`callback_task` 表，status: pending/processing/done/dead），串行保证顺序。
- HTTP 客户端超时 5s（对齐企微）；成功判定：HTTP 200 且 body 为空串 / `success`，或 body 为合法 `{"encrypt":...}` 被动回复（解密成功即回复落群）。
- 重试 3 次仍失败入 `dead`，控制台可手动重推。
- 进程启动时把遗留 `processing` 复位为 `pending`。
- 流式轮询：被动回复 `finish=false` 时，以固定节奏（默认 1s，可配置）继续向回调 URL 推送流式刷新回调（同走加密信封与重试），6 分钟窗口，直至 `finish=true`。

### 5.5 response_url 主动回复（`internal/api/respond.go`）

- 生成回调任务时签发 `response_code`（随机不可猜测），落库带过期时间（1 小时）与使用标记；`response_url` 的 Base 地址取启动配置 `-public-url`（接入方与平台不同机时配置局域网地址），缺省用监听地址。
- `POST /cgi-bin/aibot/response?response_code=xxx`：校验有效性与一次性语义；消息以机器人身份落入回调来源群，并自动引用触发回调的用户消息（对齐官方群聊主动回复行为）。
- 已用 / 过期 / 非法 code 返回对应 errcode，收录错误码对照表。

### 5.6 群聊客户端与 @ 解析

- 登录二选一：选择预置用户（示例用户/控制台创建）或输入昵称自动注册新 userid；登录即 userid 绑定 WS 连接；同 userid 多连接全量推送。
- 发送框支持 `@` 自动补全（群成员 + 群内机器人）；命中机器人即在服务端生成回调任务（对齐企微"只有 @机器人 触发回调"的行为）。
- 机器人消息（webhook 发送 / 被动回复 / response_url 回复）以机器人身份渲染在群里，带 bot 标识；流式消息按刷新事件分段更新渲染。

### 5.7 回环自测（`make selftest`）

- `im-server -selftest`：进程内启动平台 + mock 接入方，自动跑完 M1 验收全链路——echostr 验证 → 加密推送 → 验签解密 → 被动回复 → response_url → 流式状态机 → 死信重试——断言全部通过，作为日常回归与 CI 用例。
- **分工**：selftest 的加解密实现与平台同源，用于回归分发/重试/流式状态机；**跨实现互通**由 `examples/pingbot-python`（官方 WXBizMsgCrypt 库）实测承担，二者缺一不可。
- **golden fixtures**：加密信封、回调 JSON、被动回复包体、错误响应等协议报文各存一份样例文件，selftest 逐字节比对，防协议漂移。

## 6. 部署与接入

### 6.1 启动

```bash
make run          # 默认 :7788；首次启动自动初始化数据目录
make selftest     # 回环自测：跑完 M1 验收全链路（CI 可用）
./im-server -addr :7788 -public-url http://192.168.1.10:7788 -data ./data [-tls]
```

`-public-url`：平台对外可达地址（生成 response_url 与启动日志中的接入地址）；本机联调可缺省（用监听地址），局域网协作必填。

控制台：`http://127.0.0.1:7788/admin`；IM 客户端：`http://127.0.0.1:7788/`。

首次启动日志直接打印（开箱即用）：

```
示例机器人 webhook:  http://127.0.0.1:7788/cgi-bin/webhook/send?key=693a91f6-...
回调配置: Token=...  EncodingAESKey=...（在控制台保存回调 URL 后生效）
```

### 6.2 接入方切换

| 企微 | 本平台 |
|---|---|
| `https://qyapi.weixin.qq.com` | `http://127.0.0.1:7788`（或局域网 IP） |
| 机器人 webhook key / 回调三元组 | 控制台创建机器人后获得（示例机器人开箱即有） |

- 机器人接入一般是"裸 HTTP 服务 + 官方 WXBizMsgCrypt 加解密库"，加解密库无域名依赖，改 Base URL 即可；`receiveid` 参数置空字符串。
- 完整迁移步骤（含 curl 冒烟用例）见设计文档 §8.4。
- 对硬编码企微域名的接入方：`/etc/hosts` 把 `qyapi.weixin.qq.com` 指向本机 IP + 平台开 TLS（自签证书加入信任），M3 提供脚本。

### 6.3 局域网协作

平台监听 `0.0.0.0`，同网段同事可访问客户端与 API；接入方的回调 URL 可填同事本机地址——这也是"免内网穿透"的核心收益（企微云端明确不接受内网 URL，本地平台没有此限制）。跨机器协作时记得配置 `-public-url` 为局域网地址，保证 response_url 对接入方可达。

## 7. 验收标准

**M1a（一次性回复闭环）：**

1. 接入方仅改 Base URL，`POST /cgi-bin/webhook/send` 发送 text/markdown 成功，Web 客户端群内收到机器人消息，`mentioned_list` 与 `<@userid>` 生效。
2. 控制台配置机器人回调后，接入方用**企微官方加解密库**（receiveid 置空）能通过 URL 验证并正确解密推送的消息 JSON（msgid/aibotid/chatid/chattype/from.userid/response_url/msgtype/text.content 字段正确）。
3. 用户在客户端 @机器人 回复，接入方在 3 次重试内收到并验签成功；接入方回 `success` 或加密被动回复（`finish=true` stream）后无重复推送（按 msgid 幂等），回复正确落群。
4. response_url 闭环：接入方用回调中的 response_url 主动回复 markdown，消息落群并引用触发消息；重复调用 / 过期调用返回对应 errcode。
5. `make selftest` 通过（含 golden fixtures 报文比对）；`examples/pingbot-go` 与 `examples/pingbot-python`（官方加解密库）实测通过。
6. 交付 `docs/错误码对照表.md` 与 `docs/errorcodes.json`。

**M1b（流式、模板卡片与 TLS）：**

7. 被动回复流式闭环：接入方返回加密的 `finish=false` stream 回复，平台按 1s 节奏（可配置）在 6 分钟窗口内轮询推送流式刷新回调，接入方每次应答全量内容，客户端分段渲染直至 `finish=true`。
8. template_card 被动回复与 response_url 回复落群，客户端正确渲染。
9. TLS 模式：开启自签证书后，https 接入方（已信任 CA）完成上述全部流程。

**通用（M1b 结束时）：**

10. 平台重启后：机器人、群、用户、消息历史、回调配置均不丢失；pending 回调恢复推送；未完成的流式会话按超时结束。
11. 配置 `-public-url` 后，跨机器接入方可完整走通 1–4（response_url 可达）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| ~~智能机器人回调 JSON 字段细节拿不准~~ | ~~接入方解密后解析失败~~ | **已解除**：2026-08-28 对照官方文档 101039/100719/101031/101138/101841/91770/90930 锁定基线（设计文档 §7.4）；实现期偏差即停线修正；明文模式辅助排查 |
| 智能机器人能力迭代快（模板卡片交互、新事件） | 协议漂移 | 只承诺字段级对齐锁定时的文档版本；变更走平台小版本升级并更新 §7.4 |
| 接入方 SDK 硬编码企微域名 | 无法仅改 Base URL | M1a 交付 `examples/` 与已验证接入方式清单明确可用路径；hosts + 自签证书方案兜底（M3 脚本） |
| 接入方依赖 HTTPS | http 下 SDK 拒绝请求 | TLS 自签证书 M1 内置，一键开启 |
| WXBizMsgCrypt 实现偏差 | 验签/解密失败 | 官方测试向量单元测试；M1 验收要求官方加解密库实测互通；明文模式排查 |
| 单进程重启中断推送 | 少量消息延迟 | 队列持久化 + 启动恢复（已设计） |

## 9. 与 testweb demo 的关系

- demo 验证了形态（Go + 嵌入式 React + WS + 群聊 + webhook），其"群聊客户端 + webhook 推送"正是智能机器人接入的最小写照，架构方向直接延续。
- 新平台协议完全对齐企微（demo 是自有 webhook 协议、只发不收），二者不共享代码；待 M1 稳定后 demo 可移除。
